# Blender lessons for the Open World Format and LocalGPT Gen

**Source studied:** `external/3d/blender` at 5.4 alpha (commit 3fe0f2ab, 2026-10-17). Blender is GPL-2.0-or-later and is read-only reference material: this report describes mechanisms and designs so we can adopt *patterns*; no Blender code is to be copied into either project (both are Apache-2.0). File pointers are under `source/blender/`. Marks: **adopt** (as described), **adapt** (idea fits, mechanism does not), **avoid** (does not map, or we already do better).

## 1. DNA and RNA: schema, reflection, old files

**Blender.** `makesdna/intern/makesdna.cc` parses every `DNA_*_types.h` into SDNA tables embedded in each `.blend` (`DNA1` block). On read, `DNA_struct_get_compareflags` (`makesdna/intern/dna_genfile.cc:991`) compares the file's structs with the binary's and `DNA_struct_reconstruct` rebuilds changed blocks *member by name* (missing member: zero; changed primitive: cast). Renames are declared once in `makesdna/intern/dna_rename_defs.h`; semantic migrations are hand-written in `blenloader/intern/versioning_NNN.cc`, each guarded by `MAIN_VERSION_FILE_ATLEAST(bmain, 500, 13)` against a (version, subversion) pair in `BKE_blender_version.h`, run oldest-first by `do_versions` (`readfile.cc:3876`) and again after pointers resolve. `FileGlobal::minversion` names the oldest Blender that can read a file (`readfile.cc:1199`), and `DNA_DEPRECATED` members stay in structs for older readers. RNA is runtime reflection over DNA: `RNA_def_property(srna, "location", PROP_FLOAT, PROP_TRANSLATION)` with `_ui_range`, `_editable_array_func`, `_update(NC_OBJECT | ND_TRANSFORM, ...)` (`makesrna/intern/rna_object.cc:3190`), and `DeprecatedRNA{note, version, removal_version}` (`RNA_types.hh:1143`). The UI is generated from it: `uiLayout::prop` ends in `uiDefAutoButR` (`editors/interface/interface_utils.cc:57`), choosing the widget from property type and *subtype*.

**For openworldformat:** *adopt* a (version, subversion) migration ladder: schema v3 is one number, and five references will each need "read a package written at 3.x" steps; an ordered, guarded list per reference plus a conformance corpus of old packages keeps them aligned. *Adopt* `min_reader_version` in `package.json` (the `minversion` idea; the "Safe Mode" boot has nothing to read today). *Adopt* subtype annotations beside `x-entity-ref` (`x-unit: degrees|meters|lumens`, `x-color: srgb|linear`) so generic editors pick widgets and conversions from the schema. *Avoid* SDNA-style reconstruction: JSON must-ignore plus merge patch already is member-by-name.

**For LocalGPT Gen:** *adopt* the `uiDefAutoButR` rule for the detail panel's generic JSON editor: one table from (type, subtype, range, description) to widget, written once for the Bevy UI port, so a new variant draws itself. *Adapt* `DeprecatedRNA` as `x-deprecated: {since, removal, note}` so the panel greys a field rather than hiding it.

## 2. Undo

**Blender.** `blenkernel/BKE_undo_system.hh` is a linear `UndoStack` of `UndoStep`s typed by `UndoType{step_encode, step_decode, step_foreach_ID_ref}`. `BKE_undosys_step_push_with_type` (`blenkernel/intern/undo_system.cc:529`) frees every step after the active one, then encodes; `BKE_undosys_step_load_data_ex` (`:783`) decodes step by step toward the target, skipping steps marked `skip` (grouped and internal steps). Global undo is **memfile**: the whole `Main` is written through the normal file writer into memory chunks, `BLO_memfile_chunk_add` (`blenloader/intern/undofile.cc`) shares chunks byte-identical to the previous step's, and on decode `read_libblock_undo_restore_identical` (`readfile.cc:3348`) moves unchanged IDs from the old `Main` into the new one by `session_uid`. Per-mode undo types keep their own deltas and re-resolve data-block pointers by name (`UndoRefID`). `ED_undo_push` (`editors/undo/ed_undo.cc:103`) runs from `wm_operator_finished` when the operator type carries `OPTYPE_UNDO`; `ED_undo_operator_repeat` (`:879`) is "Adjust Last Operation": pop the step, re-execute the operator with edited properties. One user, one stack; no per-author undo.

**For openworldformat:** *avoid* the stack: an appended inverse on a tree is strictly more capable for many authors, and the redo-kill is what branches replace. *Adapt* chunk sharing for snapshots: per-entity, content-addressed keyframes would let `snapshots/` and `FoldCache` share unchanged entities (a note for the branching RFC). *Adopt* explicitness about skipping: say that undo and redo marker entries (`via`, `of`) are skipped when finding "the newest batch nobody has undone", as Blender's `skip` flag is.

**For LocalGPT Gen:** *adopt* "Adjust Last Operation": after a gesture commits, the HUD shows the batch's parameters; editing them undoes the person's own newest entry and submits the edited batch as one atomic pair. The own-scope undo's refusal when a later batch built on the same entities is exactly `ED_undo_operator_repeat`'s precondition. *Adopt* "undo is declared by the operation": a `PersonIntent` says whether it produces an entry (selection, hover and camera do not), as `OPTYPE_UNDO` does.

## 3. Operators and the event system

**Blender.** Every action is a `wmOperatorType` (`windowmanager/WM_types.hh:1103`): `exec`, `invoke`, `modal`, `cancel`, `poll`, an RNA struct of declared properties, flags (`OPTYPE_REGISTER | UNDO | BLOCKING | GRAB_CURSOR_XY`). A drag is a modal operator registered with `WM_event_add_modal_handler` (`wm_event_system.cc:4785`), which freezes the area and region it started in and receives every later event first. A **modal keymap** (`WM_modalkeymap_ensure`; "Transform Modal Map", `editors/transform/transform.cc:839`) translates raw keys to semantic items (`EVT_MODAL_MAP` carrying `TFM_MODAL_AXIS_X`) before the operator sees them, so mid-drag keys are rebindable. On `OPERATOR_FINISHED`, `wm_operator_finished` stores the properties on the type (`WM_operator_last_properties_store`, `wm_operators.cc:939`, re-applied on the next invoke unless `PROP_SKIP_SAVE`), pushes undo, registers the operator for the HUD (`WM_operator_last_redo`), and logs its Python string (`WM_operator_pystring` as `RPT_OPERATOR`, `wm_event_system.cc:1244`): every GUI action lands in the Info editor as the call that reproduces it. Macros (`WM_operatortype_append_macro`) chain operators (duplicate, then move). Shared property sets exist, e.g. `WM_operator_properties_mouse_select` (`extend`, `deselect`, `toggle`, `deselect_all`; `wm_operator_props.cc`).

**For openworldformat:** *adapt* the pystring through the existing `tool` history kind: an authority records a person's gesture (`{"tool": "canvas.translate", "args": {"axis": "x", "delta": 0.5, "snap": true}}`) in the entry with its edits, so the log reads as intent plus effect and agents learn the vocabulary from history. *Avoid* last-properties in the format.

**For LocalGPT Gen:** *adopt* the operator split. `canvas_edit.rs` fuses gesture tracking and the edit; Blender's shape is `{params: serde struct, exec(params) -> batch, modal(event) -> params}` per tool. A drag ends by calling `exec`; a key nudge calls it with a preset; the HUD re-calls it; an agent calls it over HTTP (`POST /tools/translate`). *Adopt* modal keymaps for drags (section 4). *Adopt* the mouse-select property set as the one rule for Shift, Cmd/Ctrl and click-on-nothing; the Shift/Q collision came from modifiers decided in several places. *Adopt* macros for duplicate-then-drag: one entry, two tools.

## 4. Transform and gizmos

**Blender.** `editors/transform/` is one modal operator family. `TRANSFORM_OT_translate/rotate/resize` share a declared property set chosen by flags (`transform_ops.cc:640-835`: `value`, `constraint_axis`, `orient_type`, `snap`, `mirror`, `use_accurate`, `release_confirm`, mostly `PROP_HIDDEN`). `transform_invoke` goes modal unless `value` is set, then runs `transform_exec` (`:541`); `saveTransform` (`transform.cc:1832`) writes the final `value`, `orient_type`, `snap_elements`, `mirror` back into the properties so the redo panel and scripts see the exact result. Constraints come from the modal map (X/Y/Z, Shift+X planes, C clears, a second press cycles orientation) through `setUserConstraint` (`transform_constraints.cc`). Increment snap is `step * roundf(loc / step)`, with `step * precision` while `MOD_PRECISION` is held (`snap_increment_apply`, `transform_snap.cc:1722`); scene snapping raycasts to vertices, edges and faces (`transform_snap_object.cc`, `SCE_SNAP_TO_*`) from a chosen snap *source*. Numeric input (`editors/util/numinput.cc`) accumulates typed digits per axis and renders the header text. Precision applies to the mouse *delta* from the moment Shift is held (`transform_input.cc:508`), so nothing jumps. Gizmos (`windowmanager/gizmo/WM_gizmo_types.hh:373`) bind to an RNA property (`WM_gizmo_target_property_float_set` writes it and fires `RNA_property_update`) or to an operator (`WM_gizmo_operator_set`): each transform arrow is `TRANSFORM_OT_translate` with `constraint_axis` preset and `release_confirm` (`transform_gizmo_3d.cc:1812-1863`), so a handle drag *is* the keyboard operator. The arrow's modal (`gizmo_library/gizmo_types/arrow3d_gizmo.cc:333`) projects the mouse ray onto the arrow's plane and rounds by `incremental_snap_step` when the "Generic Gizmo Tweak Modal Map" says `SNAP_ON` (Ctrl) or `PRECISION_ON` (Shift) (`scripts/presets/keyconfig/keymap_data/blender_default.py:7034`).

**For openworldformat:** nothing beyond the `tool` record above.

**For LocalGPT Gen:** *adopt* handles-as-shortcuts: arrows, rings and the cube invoke the same tool `exec` with a preset constraint, removing the separate paths of `handle_edits`, `key_edits` and the panel's drag values. *Adopt* axis and plane constraint keys during a drag, a second press for local axes, C to clear (`L` is a global toggle today). *Adopt* precision on the delta from the moment the modifier is held. *Adopt* numeric input mid-drag (digits, `-` negates, Tab next axis, Enter) shown in the bottom bar; it is a key accumulator, not a text widget, so it does not wait on feathers. *Adapt* scene snapping: `bevy_picking` already raycasts, so vertex and face snap with an explicit source is within reach; our grid and 15 degrees are `SCE_SNAP_TO_INCREMENT` plus `SCE_SNAP_ROTATE`. *Avoid* proportional editing and multi-point snap.

## 5. Outliner

**Blender.** `editors/space_outliner/` rebuilds the tree from scratch (`outliner_build_tree`, `outliner_tree.cc:1205`) through one `AbstractTreeDisplay::build_tree` per display mode (`tree/tree_display.hh:167`). Expand and selection state survive rebuilds because each `TreeElement` is matched to a persistent `TreeStoreElem{type, nr, flag, id}` (`DNA_outliner_types.h:122`) by hash (`check_persistent`), saved with the file. Drag and drop is the window manager's generic `wmDrag` with `WM_DRAG_ID` payloads (`outliner_item_drag_drop_invoke` adds every selected ID with its parent) and `wmDropBox`es per region with `poll`, `copy`, `cancel`, `tooltip` (`outliner_dropboxes`, `outliner_dragdrop.cc:1914`). `parent_drop_poll` (`:365`) paints `TSE_DRAG_INTO | BEFORE | AFTER` (top and bottom quarter of a row insert before or after, the middle into), and `parent_drop_invoke` reparents with `keep_transform = !Alt`. The context menu is one operator per domain with an enum property (`OUTLINER_OT_object_operation`, `outliner_tools.cc:2772`). Filters are a bitfield (`SO_FILTER_*`) plus a shell glob on names, applied after the build. Selection sync uses two levels of dirty flags: editors tag `wm->outliner_sync_select_dirty`, `ED_outliner_select_sync_flag_outliners` (`outliner_sync.cc:85`) fans it out to each outliner, which syncs on its next draw.

**For openworldformat:** *avoid* Blender's one wrong choice for us: expand state in the document. Keep it in `.live/`.

**For LocalGPT Gen** (the next port): *adopt* rebuild-on-revision with per-id persistent row state in a resource, the structural fix for the stale row after a reparent. *Adopt* the three drop zones with an insert line and Alt for "do not keep transform". *Adopt* one `PersonIntent::Outliner(OutlinerOp)` enum for the context menu, and glob plus type filters. *Adopt* the dirty-flag sync so the canvas, the panel and `GET /selection` read one `InspectorSelection`.

## 6. IDs, names and remapping

**Blender.** `ID` (`makesdna/DNA_ID.h:418`) carries `name[258]` with a two-letter type prefix, a user count `us`, a runtime monotonic `session_uid` (`blenkernel/intern/lib_id.cc:1575`), `tag`, `recalc`. Names are unique per (type, library): `BKE_id_new_name_validate` (`lib_id.cc:1999`) with `IDNewNameMode::RenameExistingNever | Always | SameRoot` deciding who gets the `.001` suffix (`main_namemap.cc`). Every reference is enumerated by one mechanism, `IDTypeInfo::foreach_id` via `BKE_library_foreach_ID_link` with flags (`IDWALK_CB_NEVER_NULL`, `IDWALK_CB_USER`, `BKE_lib_query.hh:37`); remapping (`lib_remap.cc`) walks the same enumeration. Deletion (`lib_id_delete.cc:260`) remaps every usage of the doomed IDs to null first, tells editors, then frees; a "never null" usage (an object's mesh) deletes the user too. `Main` (`BKE_main.hh:243`) is one list per type plus `name_map`, `id_map` (session_uid lookup) and a `relations` cache.

**For openworldformat:** `schema/entity-refs.json` *is* `foreach_id`; the design is right. *Adopt* a deletion policy on the marker: `x-entity-ref: {"bind": "bindable", "on_delete": "cascade" | "clear" | "refuse"}`, with `parent` cascading (the spec already says children go), behavior targets clearing with a warning (what 0.3.6 does), and `creations[].entities` or `avatar.model_entity` refusing. Today the dangling-target warning is a special case; as marker policy, all five references compute the same outcome and the merge rules read it too. *Adopt* a stated rename rule: the spec is silent on `ModifyEntity {name: "lantern"}` when `lantern` exists; say "refuse" (an author addressing by name must not be surprised), with the `-<n>` suffix reserved for merges. *Avoid* user counts.

**For LocalGPT Gen:** *adopt* delete-as-remap: when a subtree is despawned, run the entity-refs list over the live document in the same frame, so retarget combos appear for every reference kind, not only `look_at`.

## 7. Library overrides and linking

**Blender.** A linked ID is read-only; an override (`blenkernel/intern/lib_override.cc:1672`) is a local copy whose `override_library->reference` points at the linked one and whose `properties` hold `IDOverrideLibraryProperty{rna_path, operations}`, each `REPLACE | ADD | SUBTRACT | MULTIPLY | INSERT_AFTER | INSERT_BEFORE` with `subitem_*_name/index` anchors (`DNA_ID.h:185-275`). Operations are *diffed*, not recorded: on undo push and save, `BKE_lib_override_library_main_operations_create` runs `RNA_struct_override_matches` (`makesrna/intern/rna_access_compare_override.cc:641`) over every overridable property. Applying is "copy the fresh reference, replay the operations onto the copy, swap its content into the local ID" (`BKE_lib_override_library_update`, `lib_override.cc:5474`); a changed library hierarchy triggers `BKE_lib_override_library_main_resync`.

**For openworldformat:** the pattern for composing worlds from other worlds. *Adapt* as an extension: a linked subtree is a reference (package plus the entry it was taken at) and a patch list keyed by entity name, re-applied over the upstream's new head as Blender re-applies over a fresh copy. *Avoid* diff-on-save: Blender diffs because its edits are untyped; ours are ops, so the override list is the local ops against the linked subtree, recorded. *Adopt* `INSERT_AFTER` anchoring by id for list fields: `ModifyWorld` replaces `tours` and `creations` whole, which cannot merge across branches; a list-item op addressed by a waypoint or part id would.

**For LocalGPT Gen:** later; a linked world is an asset-shelf item.

## 8. Depsgraph: evaluated state apart from authored data

**Blender.** The graph is built from the original `Main`, and evaluation never touches originals: every evaluated ID is a copy (`deg_expand_eval_copy_datablock`, `deg_update_eval_copy_datablock`, `depsgraph/intern/eval/deg_eval_copy_on_write.cc:748-890`, pointer-remapped into the graph). Edits tag (`DEG_id_tag_update(id, ID_RECALC_TRANSFORM | GEOMETRY | HIERARCHY)`, `DNA_ID.h:1054`), `deg_graph_flush_updates` propagates, `DEG_evaluate_on_refresh` (`depsgraph_eval.cc:55`) runs the schedule, and a copy is remade only when tagged `ID_RECALC_SYNC_TO_EVAL`. Only the *active* depsgraph (`DEG_make_active`) writes results back to originals, through queued callbacks (`depsgraph_writeback_sync.cc`). The UI reads originals; renderers read `DEG_get_evaluated_*`.

**For openworldformat:** *adopt* the vocabulary in the spec: the *authored document* is what `manifest.json` and every op touch; the *evaluated state* (behaviors, modulations, physics applied) is never written back. One sentence saves every renderer the bug Gen found, where a transform read in `Update` was authored on frames with a physics step and modulated on others. *Avoid* a dependency graph in the format.

**For LocalGPT Gen:** *adopt* the split as components: the document's `Transform` stays authored and a `RenderedPose` is computed each frame from modulation, behavior and physics; handles and `scene.rendered` then read one thing. *Adopt* recalc tags: `OpsApplier` tags what a committed op changed so the reconciler re-evaluates only that.

## 9. The asset system

**Blender.** An asset is any ID with `AssetMetaData` (`DNA_asset_types.h:105`: `catalog_id` UUID plus `catalog_simple_name`, author, description, license, tags). Libraries are directories of `.blend` files indexed to `*.index.json` (`editors/asset/intern/asset_indexer.cc`) so listing does not open every file. Catalogs are a tree in a text file, `blender_assets.cats.txt` (`asset_system/intern/asset_catalog_definition_file.cc`: `VERSION 1`, then `uuid:path/to/catalog:simple_name` per line), merged on load and save with `has_unsaved_changes` and `is_deleted` flags (`AS_asset_catalog.hh:312`). Cross-file references are `AssetWeakReference{library_type, library_identifier, relative_asset_identifier}`, with the simple name as fallback when the catalog file is lost.

**For openworldformat:** `assets/<sha256>.<ext>` is stronger than a path-plus-name weak reference; keep it. *Adapt* the sidecar: the CC0 pack should ship a JSON index of `{sha256, path, name, tags, author, license, catalog}` so an app lists and filters without hashing.

**For LocalGPT Gen:** an asset shelf on Bevy UI reads that index; a drop onto the canvas is one intent spawning a `mesh_asset` entity at the hit point.

## 10. The .blend file

**Blender.** `blenloader/intern/writefile.cc` documents the layout: a header (`BLENDER17-01v0500` since 5.0), then `BHead{code, SDNAnr, old, len, nr}` blocks (`blenloader_core/BLO_core_bhead.hh:16`) where `old` is the pointer value at write time; order is render info, `TEST` thumbnail, `GLOB`, each ID followed by its direct data, libraries, `DNA1`, `ENDB` (`write_file_handle`, `:1810`). Pointers are fixed on read through `OldNewMap` (`newdataadr`, `readfile.cc:1498`), then `lib_link_all`; versioning runs before and after linking (`blo_read_file_internal`, `:4381`). Saving writes `name.blend@`, rotates `.blend1..N`, then renames over (`writefile.cc:2038-2175`). `blend_validate.cc` checks invariants after read; `readfile_tempload.cc` loads one ID from another file into a temporary `Main`.

**For openworldformat:** *adopt* the thumbnail: an optional `preview.png` at the package root, written by the authority on commit, so galleries get a picture without a renderer (`.live/preview.png` is not transported). *Adopt* temp-and-rename for `package.json` as for `manifest.json`. *Avoid* pointer remapping and a self-describing type table.

**For LocalGPT Gen:** reopen-on-checkout is already Blender's revert; nothing to add.

## 11. UI layout, regions and the keymap system

**Blender.** A screen is areas of `SpaceType`s with `ARegionType`s (`blenkernel/BKE_screen.hh`: `init`, `draw`, `listener`, `keymapflag`); `ED_area_init` attaches keymap handlers per region by flag (`ED_KEYMAP_UI | GIZMO | TOOL | VIEW2D | HEADER`, `editors/screen/area.cc:2190-2285`, enum at `ED_screen.hh:851`). `wm_event_do_handlers` (`wm_event_system.cc:4240`) routes each event: the window's *modal handlers* first (running operators, open popups), then the region under the cursor, then the area, then the window's global handlers; `WM_HANDLER_BREAK` stops the chain unless the event always passes (timers, mouse move). Inside a list, `wm_handlers_do_intern` runs UI buttons, dropboxes, gizmos, then keymaps, so a focused text field swallows keys by being an active UI handler. Keymaps are named per space and region (`WM_keymap_ensure(conf, "3D View", SPACE_VIEW3D, RGN_TYPE_WINDOW)`), have a `poll`, match on type, value and modifiers (`wm_eventmatch`, `:2406`), and user changes are stored as diffs over defaults (`wm_keymap_diff_update`). Panels redraw on notifiers (`WM_event_add_notifier(C, NC_OBJECT | ND_TRANSFORM, ...)` reaching `ED_region_do_listen`). One active tool per space and mode (`bToolRef`) owns a keymap and a gizmo group.

**For LocalGPT Gen:** this is the answer to "panel keys vs world keys". *Adopt* region-scoped keymaps with cursor routing: regions (viewport, outliner, detail, rail, bar) each own a keymap resource and a `poll`; dispatch goes modal tool, hovered region, global; a focused text field is a modal handler that breaks. That replaces five guards with one dispatcher, makes bindings data (JSON, diffed against defaults), and should land before the outliner port. *Adopt* notifier-style refresh for Bevy UI panels (`Changed<Document>` by category) over per-frame `sync_controls`. *Adopt* a small template set (`template_entity_ref` as a name search, `template_asset`). *Avoid* docking and screen layouts.

## 12. The Python API as the agent surface

**Blender.** `bpy` is RNA with Python syntax: `pyrna_struct_getattro/setattro` (`python/intern/bpy_rna.cc:4875, 5169`) map attribute access to `RNA_struct_find_property`, check `RNA_property_editable`, fire `RNA_property_update`, so API and UI come from one definition. `bpy.ops.*` goes through `pyop_call` to `WM_operator_call_py` (`wm_event_system.cc:2010`), which raises `op_undo_depth` so scripted calls neither push undo nor store last-properties unless asked; `context.temp_override(window=, area=, region=)` (`bpy_rna_context.cc`) supplies what `poll` needs. `bpy.app.handlers` (`depsgraph_update_post`, `save_pre`, `undo_post`; `bpy_app_handlers.cc:109-169`) and `bpy.msgbus.subscribe_rna` let scripts react to changes. `--background --python x.py --python-exit-code 1` (`creator/creator_args.cc`) runs headless; `G.background` gates even the undo stack (`ed_undo.cc:103`).

**For openworldformat:** *adopt* headless parity as a stated principle in the live-authoring RFC and `AGENTS.md`: every gesture a person makes is a batch an agent could have sent, and the CLI can send it (true today; say it, and the smoke proves it). *Adopt* a change feed in the reference authority (`GET /events`, server-sent: commits, proposals, selection, refusals); Blender's handlers and msgbus are what the review flow and the herdr turn marks poll for today.

**For LocalGPT Gen:** *adopt* the Info-editor log: show each gesture in the bottom bar as the HTTP call that reproduces it ("copy as curl"), which teaches agents the API by example and feeds the `tool` records of section 3. *Avoid* an embedded scripting language; HTTP plus MCP is that surface.

## 13. Other things noticed

- **Geometry nodes** (`nodes/geometry/nodes/node_geo_*.cc`): each node is `node_declare` (typed sockets) plus `node_geo_exec`, evaluated lazily with a structured log (`nodes/NOD_eval_log.hh`) that tooltips read; `NOD_inverse_eval_run.hh` changes inputs so an output takes a value (node gizmos). For `creations` with typed `inputs` the declaration pattern fits (adapt, later); for Gen, inverse evaluation is "drag a handle on an instanced part, decide which override field changes".
- **animrig** (`animrig/ANIM_action.hh`): Actions with Slots, one Action animating many IDs as a pure function of time. Avoid a keyframe system; the slot idea fits a soundtrack's curves bound to several entities.
- **IO** (`io/common/IO_abstract_hierarchy_iterator.h`): exporters separate the object hierarchy from the export hierarchy; a glTF export of `<instance>/<part>` expansions wants the same split.
- **ID properties** (`DNA_ID.h:481-490`): untyped custom properties, split since 5.0 into user and code-owned. Our schema'd `ext-*` keys are better typed; avoid untyped bags.
- **Reports and jobs** (`BKE_report`, `wm_jobs.cc`): warnings versus errors is our receipt's split; long work runs as cancellable jobs with progress, which Gen's replay and asset threads could expose in the bar.

## Top ten, ranked

1. **Gen: region-scoped keymap dispatcher** (modal tool, hovered region, global; text focus as a modal handler; bindings as JSON diffed over defaults). Fixes the input problem structurally before the outliner port. Days.
2. **Gen: tools as `{params, exec, modal}`**, handles and keys as presets into one `exec`, callable over HTTP, with a HUD "adjust last operation" that undoes-own-and-resubmits. One to two weeks.
3. **Gen: axis and plane constraint keys, precision on the delta, numeric input during drags.** Two to three days.
4. **openworldformat: `on_delete` policy on `x-entity-ref`** (cascade, clear, refuse) implemented from the generated list in all five references, with authoring outcome cases; plus a stated rename rule. Two to three days.
5. **Gen: authored pose versus rendered pose as separate components, with recalc tags from `OpsApplier` into the reconciler.** Days.
6. **openworldformat: spec text for authored document versus evaluated state; `min_reader_version` in `package.json`; a (version, subversion) migration ladder with a conformance corpus of old packages.** Days.
7. **Reference authority and Gen: `GET /events` change feed** (commits, proposals, selection, refusals) so review and turn marks stop polling. Days.
8. **Gen: outliner on Bevy UI** built on rebuild-on-revision, per-id persistent row state, before/after/into drop zones, Alt for no-keep-transform, glob and type filters. Three to four days.
9. **openworldformat: optional `preview.png` at the package root, written on commit, and temp-and-rename for `package.json`.** Hours.
10. **openworldformat: list-item ops anchored by id for `tours` and `creations`, and a linking extension as reference plus recorded patch list** (design RFC first). Weeks.
